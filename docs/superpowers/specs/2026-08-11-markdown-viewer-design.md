# 챕터 읽기 마크다운 뷰어 — 설계

작성일: 2026-08-11

## 배경

`./guide` → "챕터 읽기"(`scripts/reading.py`)는 챕터 본문을 **가공 없이** `$PAGER`로
넘긴다. 읽는 사람은 `#`, `**`, `` ` ``, `|`, `- [ ]` 같은 마크업 기호를 그대로 본다.
확인된 불편은 네 가지 전부다.

1. 표가 어긋난다 — 한글이 섞인 파이프 표는 소스 상태로 열이 맞지 않고, 치트시트처럼
   넓은 표는 터미널 폭을 넘어 `less`가 접으면서 정렬이 무너진다.
2. 제목·구조가 눈에 안 들어온다 — `#`/`##`/`###`가 전부 같은 흰 글씨라 챕터의 4단
   구조(핵심 개념 / 명령어 / 실습 / 체크리스트)가 스캔되지 않는다.
3. 코드블록이 본문과 구분되지 않는다 — ` ```sql `/` ```bash ` 블록이 설명 문장과 같은
   색·같은 들여쓰기로 섞여 "여기부터 실행할 명령"이 보이지 않는다.
4. 강조·인라인 코드 기호가 잡음이다.

챕터가 실제로 쓰는 마크다운 분포(01/02/03 티어 + appendix 기준):

| 요소 | 개수 |
|---|---|
| 인라인 코드 `` `…` `` | 922 |
| 굵게 `**…**` | 708 |
| 제목 `#`~`######` | 537 |
| 불릿 `-`/`*` | 523 |
| 표 본문 줄 `\|…` | 324 |
| 코드펜스 | 247 (sql 114, bash 94, ini 12, text 9, yaml 7, markdown 5, hcl 5, conf 1) |
| 체크박스 `- [ ]` | 239 |
| 수평선 `---` | 78 |
| 인용 `>` | 37 |
| 링크 `[…](…)` | 2 |

표와 인라인 코드가 압도적이고 링크는 사실상 없다. 이 분포가 렌더러 범위를 정한다.

## 목표

챕터 본문을 마크다운 서식이 적용된 형태로 보여 준다. **스크롤·검색은 계속 `less`가
한다** — 뷰어를 새로 만들지 않는다(`CLAUDE.md`: curses 안에서 터미널 도구를 다시
만들지 않는다. SQL 콘솔 363줄이 같은 이유로 지워졌다).

## 비목표 (YAGNI)

- 이탤릭 `*한 개*` — 본문 별표와 오탐 위험이 크고 챕터에서 거의 쓰지 않는다.
- SQL/bash 신택스 하이라이팅 — 코드블록 구분은 테두리+색으로 충분하다. 별건.
- 원본/렌더 토글 스위치.
- 이미지, 원시 HTML 태그, 중첩 표, 각주, 정의 목록.
- `exam`/`shoot`의 화면 변경. 이 작업은 읽기 모드에만 닿는다.

## 1. 구조

파이프라인은 **벤더 필터 → 렌더 → 페이저** 세 단계다.

```
chapter_text(rel, dbms)      # 기존. filter_dbms.filter_lines 그대로
      ↓ 마크다운 텍스트
markdown_render.render(...)  # 신규
      ↓ ANSI 입혀진 평문(또는 무색 평문)
tui.page_text(...)           # 기존. -R 보강만 추가
```

`chapter_text()`는 손대지 않는다. 벤더 필터링과 렌더링이 한 함수에 섞이면
`generate-branch.sh`와 공유하는 필터 로직의 경계가 흐려진다.

### 신규 모듈: `scripts/markdown_render.py`

표준 라이브러리만 사용. `curses`를 import하지 않고 파일·프로세스 I/O도 하지 않는다.
폭 계산은 `tui.cwidth()`를 재사용한다(전각 처리를 두 번 구현하지 않는다).

공개 API는 하나다.

```python
def render(text, width=80, color=True) -> str
```

내부는 3층으로 나눈다. 각 층은 순수 함수이고 독립적으로 테스트한다.

| 함수 | 입력 → 출력 | 책임 |
|---|---|---|
| `inline_spans(text)` | `str` → `[(글자, 스타일), …]` | 인라인 마크업 파싱 |
| `layout(spans, width)` | span 목록 → 줄별 span 목록 | 표시 폭 기준 줄바꿈 |
| `paint(line_spans, color)` | 줄별 span → `str` | ANSI 부착 또는 평문화 |

**이 3층 분리가 설계의 핵심이다.** `**굵게**`를 ANSI로 먼저 바꾼 뒤 줄바꿈하면
`\x1b[1m`이 폭 계산에 잡혀 우측 여백이 들쭉날쭉해지고, 스타일이 줄 경계에서 끊겨
`less`에 번진다. 폭은 반드시 색이 붙기 전에 잰다.

표 셀도 같은 3층을 통과한다 — 셀 안에 인라인 코드와 굵게가 들어 있고, 셀 줄바꿈은
문단 줄바꿈과 같은 문제다.

스타일 이름은 문자열 상수로 둔다(`"bold"`, `"code"`, `"h1"`, `"h2"`, `"h3"`,
`"fence"`, `"quote"`, `"dim"`, `"th"`, `None`). ANSI 코드 매핑은 `paint()` 안의
딕셔너리 한 곳에만 있다.

### 블록 파서

`filter_dbms.filter_lines`와 같은 줄 단위 스캐너로 쓴다. 챕터가 쓰는 마크다운
부분집합이 좁고 일정하므로 범용 파서가 필요 없다.

**코드펜스 안에서는 모든 마크업 해석을 끈다.** `filter_lines`가 `in_fence`를
추적하는 것과 같은 이유다 — SQL 주석 `-- …`, bash의 `## …`, C의 `**ptr`가 펜스
안에 있을 수 있다.

## 2. 요소별 렌더 규칙

### 블록

| 소스 | 렌더 | 색 없을 때 |
|---|---|---|
| `# 제목` | `━━━ 제목 ━━━` (굵게+밝게) | 기호 그대로 유지 |
| `## 제목` | `◆ 제목` (굵은 청록) | `◆ 제목` |
| `### 제목` 이하 | `· 제목` (굵게) | `· 제목` |
| ` ```lang ` … ` ``` ` | `┌─ lang ─────` / 각 줄 `│ ` / `└─────`, 노랑 | 테두리 유지 |
| 파이프 표 | 폭 배분 + 셀 내 줄바꿈, 헤더 굵게, 구분선 `─` | 정렬 유지 |
| `- 항목` | `• 항목` (2단계 `◦`, 3단계 이상 `-`, 들여쓰기 보존) | 동일 |
| `1. 항목` | 번호 유지 | 동일 |
| `- [ ]` / `- [x]` | `☐` / `☑` | 동일 |
| `> 인용` | `│ 인용` (흐리게) | `│ 인용` |
| `---` / `***` | 폭만큼 `─` (흐리게) | 폭만큼 `─` |
| `<!-- … -->` | 숨김 | 숨김 |
| 그 외 문단 | 폭에 맞춰 줄바꿈 | 동일 |

HTML 주석 숨김은 요청 범위 밖의 덤이다. `chapter_text()`는 `dbms`가 주어진
경우에만 `filter_lines`를 부르므로(`reading.py:60-61`), **"전체" 보기로 읽으면
`<!-- dbms:postgresql -->` 마커가 본문에 그대로 노출된다.** 같은 규칙 한 줄로
이 기존 잡음까지 사라진다.

### 인라인 — 색 유무로 규칙이 갈린다

| 소스 | 색 있음 | 색 없음 |
|---|---|---|
| `` `코드` `` | 백틱 제거 + 시안 | `` `코드` `` 그대로 |
| `**굵게**` | 별표 제거 + 굵게 | `**굵게**` 그대로 |
| `[글자](url)` | `글자` 밑줄 + ` (url)` 흐리게 | 소스 그대로 |

**색이 없으면 기호를 남긴다.** 구분 수단이 사라졌는데 기호까지 지우면 정보가
사라진다. 색이 있을 때만 기호를 색으로 대체한다.

### 표 폭 배분

1. 각 열의 최장 셀 표시 폭(`cwidth`)을 구한다. 열 사이 여백은 1칸.
2. 합이 `width` 안에 들어가면 그대로 쓴다.
3. 넘치면 넓은 열부터 깎아 배분하고, 넘치는 셀은 `layout()`으로 셀 안에서 접는다.
   접힌 둘째 줄부터는 다른 열이 비고 해당 열만 이어진다.
4. 열 최소 폭은 `cwidth("가나") == 4` 정도로 두어 0폭 열이 생기지 않게 한다.

헤더 아래 구분선(`|---|---|`)은 열 폭만큼의 `─`로 다시 그린다. 소스의 정렬
지시자(`:---`, `---:`, `:---:`)는 읽어서 셀 정렬에 반영한다.

### 색 팔레트

8색 ANSI(SGR 30–37 + 굵게 1 + 흐리게 2 + 밑줄 4)만 쓴다. 256색·트루컬러는
쓰지 않는다 — 어떤 터미널에서도 깨지지 않는 쪽이 중요하다.

| 스타일 | SGR |
|---|---|
| h1 | `1;36` (굵은 청록) |
| h2 | `1;36` (굵은 청록) |
| h3 이하 | `1` (굵게) |
| 인라인 코드 | `36` (청록) |
| 굵게 | `1` |
| 코드펜스 본문 | `33` (노랑) |
| 코드펜스 테두리·언어 라벨 | `2` (흐리게) |
| 표 헤더 | `1` (굵게) |
| 인용·수평선·URL | `2` (흐리게) |

h1과 h2가 **같은 색인 것은 의도다.** 단계 구분은 접두 장식(`━━━ … ━━━` 대 `◆`)이
지고, 색은 늘리지 않는다 — 8색 안에서 임의 색을 하나씩 더하면 터미널 배경마다
읽히지 않는 색이 생긴다. 인라인 코드가 h2와 같은 청록인 것도 같은 이유이며,
굵게 여부로 갈린다.

표 헤더는 **굵게만** 준다. 아래에 `─` 구분선을 따로 그리므로 밑줄까지 주면 겹친다.

## 3. 색·페이저 처리 — `tui.py` 변경

### `pager_supports_color()` (신규)

렌더된 텍스트에 ANSI를 넣어도 안전한지 판정한다. `False`인 조건:

- `NO_COLOR`가 설정되어 있다(표준 관례).
- `sys.stdout.isatty()`가 거짓이다(파이프·리다이렉트).
- `TERM`이 없거나 `dumb`이다.
- `$PAGER`가 설정되어 있고 그 실행 파일 이름이 알려진 색 지원 페이저가 아니다.

알려진 색 지원 페이저: `less`, `most`, `bat`, `delta`, `moar`, `ov`.
`$PAGER`가 아예 비어 있으면 `page_text`가 `less -R`(또는 페이저 없이 `print`)로
가므로 `True`.

### `page_text()`에 `-R` 보강

`$PAGER`가 less 계열인데 인자에 `-R`/`-r`(및 `--RAW-CONTROL-CHARS` 등 장형)이
없으면 `-R`을 붙인다. 이미 있으면 건드리지 않는다. 그 외 페이저의 인자는
손대지 않는다.

### 왜 판정이 `page_text` 밖에 있나

`page_text()`는 `shoot`의 등급표·후일담 같은 **평문**도 받는다. 색을 넣을지는
부르는 쪽만 안다. 반면 페이저 명령줄 조립은 `page_text` 안에서만 일어나므로
`-R` 주입은 거기 둔다.

### `text_width()` (신규)

렌더 폭을 정한다. `shutil.get_terminal_size()`에서 가져와
`max(40, min(폭 - 2, 100))`. 가로 200칸 터미널에서 한글 문단이 한 줄로 늘어지면
오히려 못 읽는다. `get_terminal_size()`는 비-tty에서 `COLUMNS` 또는 `(80, 24)`로
떨어지므로 별도 처리가 필요 없다.

`markdown_render`가 아니라 `tui`에 두는 이유: 터미널 크기를 묻는 일이고,
`markdown_render`는 I/O 없는 순수 모듈로 유지한다(`width`는 인자로만 받는다).

## 4. 호출부 변경 — `reading.py`

```python
def read_chapter(rel, dbms=None):
    """본문을 렌더해 `$PAGER`로 넘긴다. curses 밖에서 부른다."""
    page_text(markdown_render.render(chapter_text(rel, dbms),
                                     width=text_width(),
                                     color=pager_supports_color()))
```

`chapter_text()`가 읽기 실패 시 돌려주는 안내 문장(`"… 을(를) 읽을 수 없습니다: …"`)도
그대로 렌더를 통과한다 — 마크업이 없는 한 줄이라 문단으로 출력되고, 동작에 영향이
없다.

## 5. 검증

### `tests/test_markdown_render.py` (신규)

순수 함수 테스트. curses·tty 불필요.

- 제목 3단계가 각각 다른 접두를 얻는다.
- 코드펜스가 테두리를 얻고, **펜스 안의 `## `·`**`·`|`가 해석되지 않는다.**
- 한글이 섞인 표의 열이 `cwidth` 기준으로 정렬된다(`len` 기준이면 실패하도록
  한글·영문 길이가 엇갈리는 픽스처를 쓴다).
- 폭을 넘는 표가 셀 안에서 접히고, 접힌 뒤에도 열 시작 위치가 유지된다.
- 표 정렬 지시자(`:---:` 등)가 반영된다.
- `- [ ]`/`- [x]` → `☐`/`☑`.
- 인용·수평선·중첩 불릿·번호 목록.
- `<!-- dbms:mysql -->`가 출력에서 사라진다.
- **`color=False`면 출력에 `\x1b`가 하나도 없다.**
- `color=False`면 백틱과 `**`가 보존되고, `color=True`면 제거된다.
- `layout()`이 span 경계를 넘어 줄바꿈해도 스타일이 유지된다.

### `tests/test_tui.py` (추가)

- `pager_supports_color()` 판정표: `PAGER` 미설정 / `less` / `less -R` / `more` /
  `bat` / `NO_COLOR=1` / 비-tty / `TERM=dumb`.
- `-R` 주입: `less` → `less -R`, `less -R` → 그대로(중복 없음),
  `less -RS` → 그대로, `more` → 그대로.
- `text_width()`: 좁은 터미널(30)에서 하한 40, 넓은 터미널(200)에서 상한 100,
  중간(90)에서 `폭 - 2`.

기존 테스트가 쓰는 방식대로 환경 변수와 `isatty`를 패치한다.

### `tests/test_reading.py` (추가)

- `read_chapter`가 `page_text`에 **렌더된** 텍스트를 넘긴다(원본이 아니다).
- 렌더가 **DBMS 필터 뒤에** 적용된다 — 마커가 있는 픽스처로 확인.

### 문서

## 위험과 대응

| 위험 | 대응 |
|---|---|
| `$PAGER`가 색을 못 다뤄 `ESC[1m`이 글자로 보인다 (지금보다 나빠지는 유일한 경우) | `pager_supports_color()`가 모르는 페이저면 무색. 색과 구조를 분리해 무색에서도 정렬·테두리·기호 개선이 남는다 |
| 인라인 파서가 코드 안의 `**`를 강조로 오인 | 펜스 안 해석 전면 차단 + 인라인 코드 span 안에서는 다른 마크업 미해석 |
| 표 폭 배분이 특정 챕터에서 깨짐 | 가장 넓은 두 파일을 실행 검증 항목으로 못박음 |
| ANSI가 폭 계산에 섞여 정렬이 어긋남 | 3층 구조로 구조적 차단(`paint`가 마지막) + `color=False` 무-`\x1b` 테스트 |
