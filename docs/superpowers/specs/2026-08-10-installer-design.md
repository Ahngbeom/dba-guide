# 설계 — 사용자 편의용 설치 수단 (`install.sh`)

작성일: 2026-08-10 · 기준 형상: `main@39b10ac` (= `v1.1.0`)

## 배경

이 저장소를 처음 만난 사람이 **저장소를 손에 넣는 방법이 문서 어디에도 없다.**
`rg "git clone|다운로드|releases/" README.md docs/*.md` 결과가 0건이고,
`README.md`의 `## 한 번에 시작하기`는 `./guide`부터 시작한다. 즉 이미 클론했다는
전제가 암묵적으로 깔려 있다.

동시에 `v1.1.0`에서 `./guide`가 최상위 메뉴로 들어오면서 진입점이 하나로 모였다.
읽기·점검·훈련이 한 명령 뒤에 있으므로, 설치 수단이 노출해야 할 것도 명확해졌다.

## 목표

- 저장소를 손에 넣고 실행 가능한 상태로 만드는 과정을 **한 줄**로 만든다.
- 업데이트와 제거까지 같은 수단이 책임진다.
- 학습자가 만나는 지점을 **사람이 점검한 릴리스 태그**로 고정한다.

## 비목표

Homebrew tap, PyPI/pipx, 컨테이너 이미지, Windows 네이티브 지원(WSL 안내로 갈음),
벤더 브랜치(`postgresql`/`mysql`/`oracle`) 설치, 셸 자동완성.

벤더 브랜치를 제외하는 근거는 편의가 아니라 구조다. `v1.1.0`의 `scripts/reading.py`가
DBMS를 고르게 하고 `filter_dbms.filter_lines` — 단일 벤더 브랜치를 자르는 것과
**같은 함수** — 로 본문을 걸러 보여준다. 단일 벤더로 읽으려고 브랜치를 클론할 이유가
사라졌다. 게다가 벤더 브랜치는 매번 `--force-with-lease`로 재생성되므로
(`docs/dbms-branch-strategy.md`), 이를 설치 대상으로 삼으면 업데이트가 fast-forward가
아니라 `reset --hard`가 되어 사용자 수정을 말없이 지우는 경로가 생긴다.

## 결정 요약

| 항목 | 결정 |
|---|---|
| 수단 | 저장소 루트의 `install.sh` 하나 |
| 설치 기준점 | **최신 정식 태그** (프리릴리스 `-rc` 제외) |
| 설치 경로 | `${XDG_DATA_HOME:-$HOME/.local/share}/dba-guide` |
| 노출 명령 | `$HOME/.local/bin/{guide,exam,shoot}` → 설치본 런처 심볼릭 링크 |
| 브랜치 | `main` 계열만 |
| 진입점 | `install.sh` 하나가 설치·업데이트·제거를 모두 담당 |
| 버전 | `v1.2.0` (MINOR — 더해지기만 함) |

### 왜 `~/.local/share`인가

설계 초안에서는 "학습서 본문을 에디터로 여는 게 주 용도"라는 이유로 보이는 경로를
검토했으나, `v1.1.0`의 읽기 모드가 그 전제를 없앴다. `reading.py`가 챕터를 골라
`$PAGER`로 열어 주므로 사용자가 트리를 직접 뒤질 이유가 없다. 숨김 경로는 부수적으로
"설치본은 손대지 않는다"는 신호가 되어, 로컬 수정 때문에 업데이트가 막힐 확률도 낮춘다.

### 왜 최신 태그인가

이 저장소에는 CI가 없다(`docs/release-policy.md` 「CI가 없다는 사실」). 테스트 실행,
`./shoot doctor`, 벤더 브랜치 재생성이 전부 릴리스 전 사람 손 점검이고, 그 점검을
통과한 지점에만 태그가 붙는다. `main` HEAD는 아무도 검증하지 않은 지점이므로 학습자의
기본값이 될 수 없다.

### 왜 명령 이름을 `guide`/`exam`/`shoot` 그대로 두는가

`README.md`에 `./exam` 11회·`./shoot` 12회, `docs/`에 44회 — 합쳐 67곳이 이 표기를
쓴다. 접두어를 붙이면 이 67곳 전부가 설치 사용자에게 미묘하게 틀린 문서가 된다.
이름이 일반적이라는 위험은 ① 사용자 스코프(`~/.local/bin`) 설치와 ② 설치 전 충돌
감지로 막는다.

`shoot`을 노출 대상에서 뺄 수 없는 이유는 별도로 있다. `scripts/shooting.py`는 랩이
내려가 있으면 `lab_up()`을 자동 호출하므로 플레이 시작은 메뉴만으로 되지만
(`shooting.py:3296-3300`), `guide.py`의 `main()`은 세 러너를 인자 없이 부를 뿐이라
`shoot down`·`doctor`·`notes`·`replay`가 메뉴에서 닿지 않는다. Docker 컨테이너를
내리려면 `shoot down`이 반드시 필요하다.

## 인터페이스

```
install.sh [--uninstall [--purge]] [--help]
```

| 호출 | 동작 |
|---|---|
| (인자 없음) | 설치. 이미 설치돼 있으면 업데이트. **멱등** |
| `--uninstall` | 심볼릭 링크만 제거. 저장소와 학습 기록은 남긴다 |
| `--uninstall --purge` | 링크 + 설치 디렉터리 삭제. 학습 기록 개수를 보여주고 확인을 받는다 |
| `--help` | 사용법 출력 |

`--purge`를 단독으로 주면 오용으로 보고 거부한다.

사용자에게 안내하는 형태:

```bash
# 설치 / 업데이트
curl -fsSL https://raw.githubusercontent.com/Ahngbeom/dba-guide/main/install.sh | bash

# 제거
curl -fsSL https://raw.githubusercontent.com/Ahngbeom/dba-guide/main/install.sh | bash -s -- --uninstall
```

`raw.githubusercontent.com/.../main/install.sh`를 쓴다. 설치 **대상**은 최신 태그지만
설치 **스크립트**는 `main`의 것을 쓴다 — 스크립트 자체의 버그 수정이 태그를 기다리지
않아야 하기 때문이다.

### 환경 변수

| 이름 | 기본값 | 용도 |
|---|---|---|
| `XDG_DATA_HOME` | `$HOME/.local/share` | 설치 경로 |
| `DBA_GUIDE_REPO_URL` | `https://github.com/Ahngbeom/dba-guide.git` | 클론 원본 |

`DBA_GUIDE_REPO_URL`은 테스트 이음매다. 이것이 없으면 `tests/test_install.py`가
네트워크에 의존하게 되고, CI가 없는 이 저장소에서 네트워크 의존 테스트는 사실상
아무도 돌리지 않는 테스트가 된다. `--dir` 같은 사용자용 경로 옵션은 두지 않는다.

## 동작

### 기본 모드

1. **사전 점검**
   - `git`, `python3`(≥ 3.9), `bash` — 하나라도 없으면 실패하고 설치 방법을 안내한다.
   - `docker` — 없어도 진행한다. "장애 대응 모드(`shoot`)는 쓸 수 없다"고 경고만 한다.
     읽기·점검은 Docker 없이 완전히 동작하므로 여기서 막으면 과잉이다.
   - Python 최소 버전 3.9의 근거: `scripts/shooting.py:2495`가 3.9 미만을 예외로
     처리하는 유일한 하한선이다.

2. **진입 상황 판별** — 스크립트가 놓인 자리로 두 모드를 가른다.

   | 상황 | 모드 | 동작 |
   |---|---|---|
   | `dba-guide` 작업 트리 안에서 실행 | **in-place** | 그 자리를 설치본으로 삼고 **링크만** 건다 |
   | 그 외(파이프 실행 등) | **managed** | 설치 경로에 클론/업데이트한다 |

   판별 기준은 `${BASH_SOURCE[0]}`이다. 파이프로 실행되면 이 값이 실재하는 경로가
   아니므로(`bash` 또는 빈 값) managed로 떨어진다. 실재하는 경로일 때는 그 디렉터리가
   git 작업 트리이고 **동시에** `guide`와 `scripts/guide.py`를 함께 갖고 있어야
   in-place로 본다. 두 조건을 모두 요구하는 이유는, 이름만 같은 남의 저장소 안에서
   실행됐을 때 그 자리를 설치본으로 삼는 사고를 막기 위해서다.

   **in-place 모드는 HEAD를 절대 움직이지 않는다.** 기여자가 자기 작업 클론에서
   `./install.sh`를 돌렸는데 HEAD가 태그로 detached 되면 작업이 끊긴다. 이 모드에서
   버전 관리는 사용자의 몫이며, 그 사실을 출력으로 알린다.

3. **저장소 확보 (managed 모드)**
   - 설치 경로가 없거나 비어 있으면 → `git clone` 후 최신 정식 태그로 `checkout --detach`
   - 디렉터리가 있으나 git 작업 트리가 아니면 → **중단.** 무엇이 있는지 보여주고
     직접 치우도록 안내한다. 남의 디렉터리를 지우거나 그 위에 클론하지 않는다.
   - git 작업 트리이면 → `git fetch --tags` 후 최신 정식 태그 산출
     - 현재 HEAD가 이미 그 태그면 "최신입니다"를 출력하고 **종료 코드 0**으로 끝낸다
     - **추적 파일에 로컬 수정이 있으면 중단한다.** `git status --short` 결과를
       보여주고, 되돌리는 방법과 그대로 두는 방법을 함께 안내한다. 덮어쓰지 않는다.
     - 그 외에는 `checkout --detach <태그>`

4. **최신 정식 태그 산출**

   ```sh
   git tag -l --sort=-v:refname | grep -E '^v[0-9]+\.[0-9]+\.[0-9]+$' | head -n 1
   ```

   `grep`이 프리릴리스(`v1.2.0-rc.1`)를 걸러낸다. `--sort=-v:refname`만으로는
   프리릴리스가 상위에 올 수 있으므로 패턴 필터가 필수다. 결과가 비면 중단한다.

5. **링크 생성**
   - `$HOME/.local/bin`이 없으면 만든다.
   - 세 이름(`guide`/`exam`/`shoot`) 각각에 대해:
     - 없으면 → 링크 생성
     - 우리 설치본을 가리키는 심볼릭 링크면 → 갱신
     - **그 외(일반 파일, 남의 링크)면 → 중단.** 무엇이 있는지 보여준다.
   - 중단은 세 이름을 **모두 확인한 뒤** 한 번에 알린다. 하나 걸릴 때마다 죽으면
     사용자가 같은 실패를 세 번 겪는다.

6. **PATH 확인** — `$HOME/.local/bin`이 `$PATH`에 없으면 rc 파일을 **자동 수정하지
   않고** 추가할 한 줄을 출력한다. 남의 셸 설정을 말없이 고치지 않는다.

7. **마무리** — 설치 경로, 설치된 버전, 다음 두 줄(`guide` 실행, `shoot doctor` 권장)을
   출력한다.

### `--uninstall`

- **우리 설치본을 가리키는 링크만** 제거한다. 같은 이름의 남의 파일은 건드리지 않는다.
- **설치 디렉터리는 남긴다.** `--purge`가 있어야 지운다.
- `--purge`일 때는 삭제 전에 `.exam-results/`와 `.shooting-progress/notes/`의 항목
  개수를 세어 보여주고 확인을 받는다. 비대화형(파이프)이면 확인할 수 없으므로
  **삭제하지 않고 중단**한 뒤, 직접 지우는 명령을 출력한다.

이 저장소에서 학습 기록은 `.gitignore` 대상이라 **어디에도 백업이 없는 유일본**이다.
포스트모템 노트는 `CLAUDE.md`가 "그걸 채우는 게 학습"이라고 명시한 산출물이다.
제거 명령 한 번으로 사라지면 안 된다.

### 에러 처리

`set -euo pipefail`. 모든 실패는 한국어 한 줄 + 다음에 할 일을 함께 출력한다.

| 상황 | 종료 코드 | 동작 |
|---|---|---|
| `git`/`python3`/`bash` 없음, Python < 3.9 | 1 | 중단, 설치 방법 안내 |
| `docker` 없음 | — | 경고 후 계속 |
| `~/.local/bin`에 남의 `guide`/`exam`/`shoot` | 1 | 중단, 충돌 항목 일괄 표시 |
| 설치본에 로컬 수정 | 1 | 중단, `git status --short` 표시 |
| 정식 태그 없음 | 1 | 중단 |
| 이미 최신 태그 | 0 | "최신입니다" |
| PATH에 `~/.local/bin` 없음 | 0 | 성공 + 추가할 한 줄 안내 |
| 비대화형 `--purge` | 1 | 중단, 수동 삭제 명령 출력 |

## 릴리스 순서 의존성

태그 기준 설치이므로 순서가 하나 생긴다. `install.sh`를 `main`에 머지해도
**`v1.2.0`을 발행하기 전까지 인스톨러는 `v1.1.0`을 설치**하고, `v1.1.0` 트리에는
`install.sh`가 없어 설치본 안에서 업데이트를 다시 부를 수 없다.

따라서 `v1.2.0` 발행 **직후** 실제 `curl … | bash`를 한 번 돌려 확인하는 절차가
필요하며, 이를 `docs/release-policy.md`에 적는다.

## 위험

- **`curl | bash`의 신뢰 모델.** 스크립트를 읽지 않고 실행하게 한다. 완화: README에
  다운로드 후 확인하고 실행하는 2단계 방법을 함께 적고, 스크립트를 짧고 읽을 수 있게
  유지한다.
- **점검 항목이 하나 늘어난다.** CI가 없으므로 인스톨러 검증도 사람 몫이다.
  10개 항목을 `tests/`로 자동화해 그 비용을 최소화하되, 원격 실 검증 2회는 남는다.
- **이름 충돌.** `guide`/`exam`/`shoot`은 일반적인 이름이다. 사용자 스코프 설치와
