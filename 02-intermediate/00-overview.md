# 중급 단계 개요

## 이 단계의 목표

초급 단계에서 우리는 RDBMS의 기초 이론, SQL 기본 문법, 설치/접속, 계정과 권한 관리, 기본 백업, 기본 모니터링을 다뤘다. 이제 중급 단계에서는 **실무 현장에서 DBA로서 독립적으로 운영 업무를 수행할 수 있는 수준**을 목표로 한다.

초급이 "DB를 다룰 줄 아는 사람"을 만드는 과정이었다면, 중급은 "DB를 책임지고 운영하는 사람"을 만드는 과정이다. 장애가 발생했을 때 원인을 진단하고, 성능 저하의 병목을 찾아내고, 데이터를 안전하게 보호하며, 서비스 중단 없이 변경을 적용하는 능력이 여기서 갖춰진다.

이 단계는 특정 벤더에 종속되지 않는 관계형 DB 공통 이론을 중심에 두되, PostgreSQL / MySQL / Oracle의 실제 명령어를 병기하여 실무에서 바로 활용할 수 있도록 구성했다.

## 선수 지식 (이 단계에 진입하기 위한 조건)

아래 항목은 초급 단계에서 다룬 내용이며, 중급 학습을 시작하기 전에 숙지되어 있어야 한다.

- [ ] 관계형 모델의 기본 개념(테이블, 행, 열, 기본키, 외래키, 정규화)을 이해한다.
- [ ] `SELECT / INSERT / UPDATE / DELETE`와 `JOIN`, 서브쿼리, 집계 함수(`GROUP BY`, `HAVING`)를 자유롭게 작성할 수 있다.
- [ ] `CREATE / ALTER / DROP` 등 DDL로 스키마를 정의하고 변경할 수 있다.
- [ ] PostgreSQL / MySQL / Oracle 중 최소 하나를 직접 설치하고 클라이언트로 접속해본 경험이 있다.
- [ ] 계정 생성, `GRANT`/`REVOKE`를 통한 기본 권한 부여를 할 수 있다.
- [ ] `pg_dump` / `mysqldump` / `exp(dp)` 같은 도구로 논리 백업을 받아본 경험이 있다.
- [ ] 현재 접속 세션, 실행 중인 쿼리 등 기본적인 상태 조회 방법을 안다.

위 항목 중 자신 없는 부분이 있다면 초급 단계 해당 챕터를 먼저 복습하기를 권한다.

## 이 단계를 마쳤을 때 갖추게 되는 역량

중급 단계를 모두 학습하면 다음을 할 수 있게 된다.

- **트랜잭션과 동시성 제어**: 격리 수준을 이해하고 상황에 맞게 선택하며, MVCC의 동작 원리를 설명하고, 락 경합과 데드락을 진단할 수 있다.
- **인덱스와 쿼리 튜닝**: 인덱스 종류별 특성을 알고 적절히 설계하며, 실행계획을 읽고 병목을 찾아 쿼리를 개선할 수 있다.
- **성능 모니터링**: 슬로우 쿼리를 수집·분석하고 주요 성능 지표를 해석하여 이상 징후를 조기에 발견할 수 있다.
- **백업과 복구**: 물리/논리 백업을 구분해 전략을 설계하고, PITR로 특정 시점까지 복구할 수 있다.
- **복제**: 동기/비동기 복제의 원리를 이해하고 각 DBMS의 복제 구성을 세팅할 수 있다.
- **스키마 변경 관리**: 마이그레이션 도구를 사용하고, 무중단으로 스키마를 변경하는 방법을 안다.
- **클라우드 DB 인프라 구축과 접속**: VPC/서브넷 그룹/보안 그룹을 구성해 관리형 DB 인스턴스를 직접 만들고, SSL 검증·IAM 인증·프라이빗 터널링으로 안전하게 접속할 수 있다.
- **클라우드 관리형 DB 운영**: RDS/Cloud SQL의 파라미터 그룹, 스냅샷, 버전 업그레이드, 모니터링을 다룰 수 있다.

## 고급 단계로 넘어가는 기준 (체크리스트)

아래 항목을 모두 자신 있게 "예"라고 답할 수 있다면, 고급 단계로 진입할 준비가 된 것이다.

- [ ] 4가지 트랜잭션 격리 수준의 차이와 각 수준에서 발생 가능한 이상 현상(Dirty/Non-repeatable/Phantom Read)을 설명할 수 있다.
- [ ] MVCC가 어떻게 읽기와 쓰기의 충돌을 줄이는지 설명할 수 있고, PostgreSQL의 VACUUM 필요성을 안다.
- [ ] 데드락 로그를 보고 원인이 된 두 트랜잭션과 락 순서를 파악할 수 있다.
- [ ] `EXPLAIN ANALYZE` 결과에서 Seq Scan / Index Scan / 조인 방식과 실제 소요 시간을 읽을 수 있다.
- [ ] 느린 쿼리를 받아 인덱스 추가나 쿼리 재작성으로 개선한 경험이 있다.
- [ ] 슬로우 쿼리 로그를 활성화하고 `pg_stat_statements` 또는 Performance Schema로 상위 쿼리를 뽑을 수 있다.
- [ ] 물리 백업과 논리 백업의 트레이드오프를 설명하고, 서비스 요구사항에 맞는 백업 주기·보관 정책을 제안할 수 있다.
- [ ] PITR의 개념(기준 백업 + WAL/binlog/아카이브 로그)을 이해하고 실제로 특정 시점까지 복구를 수행해봤다.
- [ ] 비동기 복제와 동기 복제의 데이터 손실 위험(RPO) 차이를 설명할 수 있다.
- [ ] 스트리밍 복제 또는 binlog 복제를 직접 구성하고 복제 지연(lag)을 확인할 수 있다.
- [ ] Flyway/Liquibase 같은 도구로 스키마 변경 이력을 관리하는 흐름을 안다.
- [ ] 대용량 테이블에 무중단으로 컬럼/인덱스를 추가하는 방법(온라인 DDL)을 안다.
- [ ] RDS 또는 Cloud SQL에서 파라미터를 변경하고 스냅샷을 생성·복원해봤다.
- [ ] 서브넷 그룹/보안 그룹(방화벽 규칙)을 구성해 관리형 DB 인스턴스를 직접 만들고, IAM 인증이나 프라이빗 터널링으로 접속해봤다.

이 체크리스트의 대부분을 채웠다면, 이제 고급 단계에서 다룰 대규모 아키텍처 설계, 고가용성 클러스터, 파티셔닝/샤딩, 심화 튜닝, 자동화로 나아갈 수 있다.
